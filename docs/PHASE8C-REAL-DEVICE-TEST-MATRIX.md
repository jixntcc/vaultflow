# Phase 8C — Real Device Test Matrix

## Purpose

Phase 8C moves mobile/desktop validation from CSS assumptions to an explicit repeatable device matrix.

This phase does **not** pretend that a simulator or static source audit is a physical-device test. The matrix is the execution checklist for real phones/tablets/desktops.

## Target matrix

| Target | Viewport | Priority |
|---|---:|---|
| Android small | 360×800 | Critical |
| Android standard | 390×844 | Critical |
| iPhone standard | 390×844 | Critical |
| iPhone large | 430×932 | High |
| Tablet | 768×1024 | High |
| Desktop | 1366×768 | Critical |
| Desktop HD | 1920×1080 | High |

### Desktop requirement

At 1366×768 and 1920×1080, Chrome/Safari/Edge must remain at **100% zoom** and show:

```text
[ metric 1 ][ metric 2 ][ metric 3 ][ metric 4 ][ metric 5 ]
```

The five-column layout must not depend on browser zoom.

## Critical flows

1. Authentication
2. Dashboard
3. Transactions
4. Vaults
5. Goals
6. Habits
7. Reports
8. Settings
9. PWA installation
10. Offline transaction synchronization
11. Backup/restore recovery

## Transaction test

The most important finance UI test:

```text
Create transaction
→ choose historical date/time
→ save
→ open Edit
→ verify original date/time
→ modify another field
→ save
→ verify date/time unchanged
→ refresh
→ verify again
```

Then repeat from a mobile device and verify Edit/Delete action visibility and touchability.

## Offline sync test

```text
Open authenticated app
→ disconnect network
→ create transaction
→ verify local pending state
→ reconnect
→ allow synchronization
→ refresh
→ verify exactly one server transaction
→ verify wallet/dashboard/report totals
```

Repeat once more to detect duplicate sync mutations.

## PWA test

On supported mobile browser:

```text
Open site
→ install VaultFlow
→ launch standalone
→ verify navigation
→ close/reopen
→ verify authenticated state according to session policy
→ temporarily lose network
→ verify offline shell
→ reconnect
```

## Backup/restore test

```text
Create representative data across domains
→ export backup
→ restore into test environment
→ verify transactions
→ verify vaults
→ verify goals
→ verify habits
→ verify automation rules
→ verify settings
→ verify calculated totals
```

## Automated part

`tests/phase8c-device-matrix-check.js` validates the static contracts required for the manual matrix:

- viewport declaration
- PWA manifest
- service worker
- five-column desktop contract
- mobile breakpoints
- 44px touch baseline
- mobile modal constraints
- safe-area handling
- all critical flow definitions

Run:

```bash
npm run test:device-matrix
```

## Important limitation

Actual physical-device results cannot be generated by a source-code test. Phase 8C therefore distinguishes:

**Automated contract validation** from **real-device execution**.

The project should not be marked "device QA complete" until the critical matrix has been manually executed on the target devices/browsers.
